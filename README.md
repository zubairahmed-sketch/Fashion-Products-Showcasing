# Fashion Products Showcasing

A two-app Vite monorepo for managing and publishing fashion products with Supabase. The **Admin** app lets staff curate products and categories, while the **Showcase** app renders a public-facing, filterable gallery.

## Repository layout

```
apps/
  admin/       # Staff-only dashboard (auth, CRUD, image upload)
  showcase/    # Public product gallery (filters, search, shuffle)
vercel.json    # SPA rewrite helper (Vercel)
```

## Tech stack

- React 18 + Vite 5
- Supabase (PostgreSQL, Auth, Storage)
- CSS modules per page/component; Lucide icons

## Applications

### Admin dashboard (apps/admin)
- Email/password auth via Supabase
- Dashboard stats (product and category counts)
- Categories: create and delete with validation
- Products: create, edit, delete; auto-assign sequential `productid`
- Image uploads to Supabase Storage with public URLs and cleanup on replace
- Resequence utility keeps `productid` contiguous after deletes

### Public showcase (apps/showcase)
- Fetches products and categories from Supabase
- Filters by category with counts
- Integer-only search by `productid` with partial matches
- Random vs ordered toggle (stable re-sort when not random)
- Responsive grid, product cards open the source URL in a new tab

## Data model (Supabase)

Recommended tables and bucket:

```sql
-- categories
id bigint generated by default as identity primary key,
name text not null unique,
created_at timestamptz default now()

-- products
id bigint generated by default as identity primary key,
productid int not null unique,
category_id bigint references public.categories(id) on delete set null,
imageurl text not null,
sourceurl text not null,
created_at timestamptz default now()

-- storage bucket
Bucket name: products
Folder: images/
Public access: enable public read or expose via signed URLs
```

If you enable Row Level Security, add policies for `select`, `insert`, `update`, and `delete` as appropriate for authenticated service roles.

## Environment variables

Create `.env.local` inside each app folder.

```
VITE_SUPABASE_URL=https://<your-project>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon-or-service-role-key>
```

Both apps read the same variables; keep keys scoped to your security needs.

## Setup

1) Install Node.js 18+.
2) Install dependencies per app:

```
cd apps/admin && npm install
cd ../showcase && npm install
```

3) Add `.env.local` files as noted above.
4) Start development servers (separate terminals):

```
cd apps/admin && npm run dev
cd apps/showcase && npm run dev
```

5) Build for production:

```
cd apps/admin && npm run build
cd apps/showcase && npm run build
```

6) Preview a production build locally:

```
cd apps/admin && npm run preview
cd apps/showcase && npm run preview
```

## Deployment notes

- Vercel: each Vite app can be deployed as its own project. Set the root to the app folder, Framework preset to Vite, and add the env vars. The root `vercel.json` supplies a simple SPA rewrite if you host from the repo root.
- Static assets are served by Vite builds; product images are served from Supabase Storage public URLs.

## Operational tips

- Product IDs are assigned sequentially on insert and resequenced after deletes to keep ordering stable in the showcase.
- Image replacement triggers deletion of the previous file when possible to avoid orphaned storage objects.
- The showcase toggles between ordered and random view; clearing search resets category to All.
